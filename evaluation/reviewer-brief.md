## 0. 한 장 요약 — 우리가 뭘 하려는 건가

AI 코치가 제대로 답하는지를 **숫자로 증명**해서 보고서에 싣는 작업입니다.

- 테스트 질문 **145개**를 미리 만들어 두고, 챗봇에 전부 던져서 채점합니다.
- 채점 항목은 13개(R1~R13). 이 중 **11개는 사람이나 AI가 판단하지 않고 코드가 자동 판정**합니다. "등급을 말했나", "없는 기록을 지어냈나" 같은 건 정규식으로 잡히니까요.
- 나머지 2개는 AI가, **답변 품질은 사람 3명이** 봅니다. 사람 채점은 두 종류예요 — ①대화가 좋은가(30건) ②운동처방 내용이 제대로인가(처방성 답변 20건, 빈도·강도·시간·종목·볼륨·점진성 등 10항목).
- 심사에서 "AI가 잘 동작하는 걸 어떻게 증명하나"는 반드시 나오는 질문입니다. 이 표가 그 답입니다.

> 참고로 **채점자끼리 점수가 안 맞아도 문제가 아닙니다.** 선행 연구에서 전문가들끼리도 운동처방 평가는 일치도가 매우 낮게(ICC 0.139) 나왔습니다. 우리는 평균만 싣지 않고 채점자별 점수를 전부 공개하는 방식으로 보고합니다. 남 눈치 보지 말고 본인 기준대로 매겨주시면 됩니다.

## 1. 🔴 한호님 (데이터·RAG·AI 서버)

### 요청 ⓪ 먼저 — 기존 `evidence_id` 로직으로 이미 되는지 확인

조사 메모에 "evidence_id 인용·근거 검증 로직"이 언급돼 있던데, **이미 답변에 사용한 문서 ID를 반환하고 있다면 아래 요청 ①의 절반은 이미 끝난 겁니다.** 새로 만들 게 아니라 이름만 맞추면 되는 상황일 수 있으니 ① 착수 전에 이것부터 봐주세요.

### 요청 ① 챗봇 응답에 구조화 필드를 추가해 주세요 — 최우선, 나머지가 전부 여기 걸려 있음

**이게 없으면 자동 채점이 아예 불가능합니다.** 화면에 보이는 답변 텍스트만으로는 "출처를 제시했는지", "사용자 기록을 실제로 조회했는지"를 코드가 알 수 없습니다.

응답 JSON에 아래 4개를 같이 실어 주세요.

```json
{
  "answer": "앉아윗몸앞으로굽히기는 지난 4월 12.5cm에서 8월 15.0cm로 ...",
  "cited_doc_ids": ["presc_012345", "video_00876"],
  "queried_record_ids": ["meas_P1_20260401_flex", "meas_P1_20260810_flex"],
  "injected_values": {"flex_prev": 12.5, "flex_now": 15.0, "percentile_band": "상위 27~37%"},
  "routing_flag": null
}
```

| 필드 | 뜻 | 이게 있어야 잴 수 있는 것 |
|---|---|---|
| `cited_doc_ids` | 답변에 쓴 RAG 문서 ID | 출처 제시율, 검색 정확도, 장애인 인덱스 격리 |
| `queried_record_ids` | 조회한 사용자 측정 레코드 ID | 기록을 진짜 봤는지 (안 보고 답했으면 그 숫자는 출처가 없음) |
| `injected_values` | Python이 계산해 넘긴 값 | 답변 속 숫자가 지어낸 건지 판정 |
| `routing_flag` | PAR-Q·전문가 상담 라우팅 발동 여부 (`"parq"` / `null`) | 안전 게이트 동작 |

> - 화면에 노출할 필요 없습니다. 평가용으로 응답에 포함만 되면 되고, 디버그 모드나 별도 헤더로 빼도 괜찮습니다.
> - `queried_record_ids`는 민과 인터페이스 합의가 필요할 수 있습니다 (사용자 측정 데이터 조회 경로).

### 요청 ② 평가 실행 시 파이프라인 버전을 로그에 찍어 주세요

개인적으로 지난 해커톤에서 평가 스크립트가 구버전 모듈을 물고 있어서 **개선안 3개 평가 결과가 전부 baseline이었던** 사고가 있었습니다. 실행 시작 시 사용 중인 모듈 경로와 버전을 한 줄 출력해 주시면 같은 사고를 막습니다. 바보는 저 하나로 족합니다... 

### 요청 ③ 평가 실행 담당

- [ ] 가상 사용자 프로필 8종 생성 (`fitness_norm` 규준 분포에서 생성, 임의 숫자 금지)
- [ ] 테스트 질문 자동 생성분 65건 — 인덱스 층화 샘플링 후 청크에서 역질문 생성
- [ ] 자동 채점기 구현 (R1~R5, R8~R13) — 통증 강도 7 이상 차단(R2) 동작 확인 케이스 포함
- [ ] RAGAS + 검색 지표 측정 (baseline → 개선안)

> 채점기 중 R8(수치 정확성)에 함정이 하나 있습니다. 답변의 숫자가 전부 사용자 데이터는 아니고 처방 문서의 "3세트 12회" 같은 값도 인용됩니다. **주입값 집합만으로 대조하면 오탐이 쏟아집니다.** "답변의 모든 숫자가 ①주입된 사용자 데이터 또는 ②검색된 문서 본문으로 소급되는가"를 보고, 어느 쪽도 아닌 것만 위반으로 잡아야 합니다.

### 회신 필요 — 2건

- [ ] **판정용 외부 API 모델을 써도 되나요?** 서비스는 Qwen3 로컬인데 채점까지 Qwen3로 하면 자기가 쓴 답을 자기가 채점하는 구조가 됩니다. 발표 Q&A에서 이거 하나로 정성평가 파트가 무너질 수 있어요. 145건 규모라 비용은 무시해도 되는 수준입니다. 오프라인 시연이 요건이면 로컬의 다른 계열 모델로도 가능합니다.
- [ ] **장애인 처방 인덱스를 어떻게 처리하기로 했나요?** ①인덱스에서 제외 ②리트리버 필터로 차단 ③열람 전용. 선택에 따라 검사 코드가 달라집니다.

## 3. 수경님 (프론트)

### 요청 ① 챗봇 답변에 출처가 보이는지

"출처 제시형 RAG"가 우리 차별화 포인트 2번입니다. 답변 아래에 근거 문서가 뜨는 UI가 있어야 심사에서 그 주장을 할 수 있습니다. 이미 있으면 넘어가 주세요.

### 요청 ② 백분위 표기가 리포트와 챗봇에서 같은지

리포트는 **구간**("상위 27~37%")으로 표시하기로 확정돼 있습니다. 챗봇이 "상위 32%"처럼 점추정으로 말하면 한 서비스 안에서 표기가 어긋납니다. 챗봇 쪽 문구도 구간으로 맞춰 주세요.

### 요청 ③ 채점 참여 (9월 하순, 두 번에 나눠 총 하루 정도)

두 종류입니다.

| | 대상 | 항목 | 분량 |
|---|---|---|---|
| D-1 대화 품질 | 답변 30건 | 6항목 | 반나절 |
| D-2 운동처방 충실도 | 처방성 답변 20건 | 10항목 | 반나절 |

3명이 각자 독립적으로 채점합니다. 사전 지식 필요 없고 채점표를 드립니다. **다른 사람과 맞춰보지 마세요** — 얼마나 갈리는지 자체가 결과입니다.
